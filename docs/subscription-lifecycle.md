# Subscription lifecycle and plan changes

The currently active purchased plan cannot be purchased again until its access expires. This rule is enforced in both billing UI and checkout/resume APIs. Other access periods remain available. A term change costs the new plan's full upfront amount and adds its period after the existing paid expiry, preserving paid time. It is not a prorated upgrade. Changing computer counts during a paid period continues through support to avoid losing time or multiplying seats. Cancel an existing automatic renewal before changing plans, then refresh billing. Provider-verified opted-in recurring charges remain supported.

Important actions use explicit confirmation dialogs: checkout/plan changes show charge, computer count, period and renewal choice; resuming checkout warns against paying twice; subscription management explains cancellation; emailing an activation key confirms its purpose and expiry. Publishing prices, granting/revoking account access and organisation access changes also require the same styled confirmations. The active-plan button automatically refreshes at expiry.

`/api/jobs/daily` requires `Authorization: Bearer <CRON_SECRET>` (at least 32 characters). It prepares emails for the 7-day, 3-day and 1-day windows and an expired notification, deletes obsolete AI sessions and expires old connection requests. Free desktop/web sessions remain valid. Organisation reminders go to the paying owner. Complimentary ongoing grants do not expire. Another valid AI grant prevents a misleading expired-access notice. Each notice is deduplicated by entitlement, paid expiry and stage. The outbox cancels stale queued notices after renewal or when their window passes.

`vercel.json` schedules the job daily at 08:00 UTC (09:00 Africa/Lagos; hosting invocation time can vary). Deploy it and configure CRON_SECRET, RESEND_API_KEY and EMAIL_FROM on the host. For other hosting, schedule an authenticated GET to the endpoint. See [Vercel cron management](https://vercel.com/docs/cron-jobs/manage-cron-jobs) for production scheduling and secret headers. Job timing controls email processing, not entitlement validity. The job sends up to 20 queued emails per run; busy sites should schedule more frequent authenticated processing where hosting permits or retry from Admin → Email delivery. Sender configuration, provider availability and quotas still apply.

AI lease expiry is capped at paid expiry; server claims/refresh and the desktop's offline signature/expiry checks enforce access independently of cron. Expired AI cannot transcribe or detect Scripture. Free Bible/media tools remain available. After another verified payment, the running updated app can claim new access automatically while online. Deploy the website and updated desktop together. Apply migration `012-subscription-notices.sql` using `npm run db:migrate`.

Checks: `npm run test:subscriptions`, billing/webhook/organisation/licensing suites, browser confirmations and desktop lease/client checks. Tests use temporary databases and simulated provider/mail requests.
